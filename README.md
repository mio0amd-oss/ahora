# فروشگاه اهورا — نمونهٔ بازطراحی‌شده

این بسته بازطراحی نمایشی فایل‌های فروشگاه اهوراست.

## ظاهر و فروشگاه
- در صفحهٔ فارسی، تصویر سربرگ ترمهٔ مرجع تنها هدر است؛ تصویر فوتر نیز تنها فوتر تصویری است. منوی پایینیِ اضافه که در موبایل فوتر دوم می‌ساخت حذف شده و لینک‌های روی تصاویر مرجع قابل کلیک‌اند.
- نسخهٔ عربی یک هدر و فوتر متنیِ عربی دارد تا نوشتهٔ فارسیِ تعبیه‌شده در تصاویر مرجع به‌عنوان ترجمهٔ عربی نمایش داده نشود.
- کارت محصول فقط یک نام و قیمت دارد. در زمان فعال‌بودن تخفیف، قیمت اصلی خط‌خورده و قیمت نهایی به‌همراه نشان تخفیف نمایش داده می‌شود.
- سبد خرید و ثبت سفارش آزمایشی با قیمت پس از تخفیف محاسبه می‌شوند. موجودی نمونه نیز از طریق پنل و پس از ثبت سفارش دمو کم می‌شود.
- جستجو، فیلتر دسته‌ها و پرفروش‌ها، سبد خرید، علاقه‌مندی‌ها، صفحهٔ حساب، کیف پول نمونه و درخواست عودت آزمایشی فعال‌اند.

## پنل مدیریت
- نشانی مستقیم فارسی: `admin.html`؛ نسخهٔ عربی: `ar/admin.html`. این نشانی‌ها از منوی عمومی فروشگاه لینک نشده‌اند و `noindex,nofollow` دارند.
- مدیریت محصولات: افزودن، ویرایش، حذف، پنهان/نمایش‌دادن، قیمت، موجودی، عنوان و توضیح فارسی و عربی، دسته و عکس نمونه.
- مدیریت پیشنهادها: تخفیف درصدی یا مبلغ ثابت، هدف‌گیری همهٔ محصولات/یک دسته/یک محصول، زمان شروع و پایان، فعال/غیرفعال‌کردن، و نمایش آن در فروشگاه.
- مدیریت محتوای اصلی: عنوان و متن بنر، معرفی فروشگاه، پیام اختیاری و نام دسته‌ها به فارسی و عربی.
- گزارش سفارش‌ها، بررسی وضعیت درخواست عودت و گزارش تراکنش‌های نمونهٔ کیف پول.
- تغییرات فروشگاه از همان مرورگر/مبدأیی دیده می‌شوند که پنل در آن استفاده شده و پس از بازکردن یا نوسازی فروشگاه اعمال می‌شوند.

## اجرا
برای آزمایش، پوشهٔ کامل را در یک وب‌سرور استاتیک (مثلاً GitHub Pages) منتشر کنید و `index.html` را باز کنید. نسخهٔ عربی در `ar/index.html` است. در صورت استفاده از `file://` بعضی مرورگرها ممکن است ذخیره‌سازی مرورگر را محدود کنند؛ اجرای محلی با وب‌سرور بهتر است.

## محدودیت مهم — برای فروش واقعی آماده نیست
این پروژه صرفاً نمونهٔ فرانت‌اند است و همهٔ اطلاعات با `localStorage` در مرورگر فعلی ذخیره می‌شوند؛ بین مشتری‌ها یا دستگاه‌ها همگام‌سازی نمی‌شوند. پنل مدیریت هیچ ورود امن یا احراز هویت سروری ندارد؛ پنهان‌بودن لینک، امنیت محسوب نمی‌شود. تا اضافه‌شدن بک‌اند و مجوز دسترسی امن، پنل را روی سایت عمومی برای داده‌های واقعی استفاده نکنید. شارژ کیف پول، پرداخت، سفارش و عودت وجه واقعی نیستند؛ تأیید/رد عودت فقط برچسب آزمایشی را تغییر می‌دهد.

برای راه‌اندازی واقعی باید بک‌اند و پایگاه داده، ورود امن مدیر و مشتری، اتصال درگاه پرداخت مورد تأیید، تأیید پرداخت سمت سرور، مدیریت واقعی موجودی/سفارش/بازپرداخت، و سیاست حریم خصوصی و ارسال/مرجوعی پیاده‌سازی شوند. اطلاعات تماس و نشانی واقعی را نیز جایگزین کنید؛ کلیدهای محرمانه را در فایل‌های عمومی قرار ندهید.

## سئو
زبان‌های مجزا، متادیتا، hreflang، دادهٔ ساختاریافته و sitemap/robots آماده شده‌اند، اما رتبهٔ اول گوگل قابل تضمین نیست. پس از انتشار، دامنه و `sitemap.xml` را در Google Search Console ثبت کنید و توضیح منحصربه‌فرد، تصویر و موجودی واقعی، سرعت مناسب، لینک معتبر و محتوای مفید فراهم کنید. نشانی canonical و sitemap در این نمونه مطابق GitHub Pages فایل‌های اولیه است؛ اگر دامنه یا مسیر نهایی فرق دارد آن‌ها را اصلاح کنید.


## نسخه V2
- اسلایدر صفحه اصلی با تعداد نامحدود بنر، تعویض خودکار هر ۱۵ ثانیه و برگشت به اولین بنر.
- مدیریت بنر از `admin.html` و تبدیل آپلودها به WebP در مرورگر.
- دسته‌بندی‌ها از پنل مدیریت قابل افزودن/حذف هستند و صفحه اصلی آن‌ها را پویا نمایش می‌دهد.
- تخفیف درصدی/مبلغی موجود است و قیمت قبلی خط‌خورده و قیمت نهایی محاسبه می‌شود.
- کد شناسایی کاربر در حساب و جستجوی پروفایل در پنل آزمایشی وجود دارد.
- پس‌زمینه ظریف ترمه‌ای و پرچم‌های محلی ایران/عربستان اضافه شده‌اند.

**محدودیت مهم:** این پروژه هنوز استاتیک و مبتنی بر `localStorage` است. تغییرات پنل مدیریت روی همان مرورگر ذخیره می‌شوند و به‌تنهایی روی GitHub Pages برای همه کاربران منتشر نمی‌شوند. برای اطلاعات واقعی مشتری، شارژ/عودت و دسترسی مدیر باید بک‌اند، دیتابیس و احراز هویت سروری اضافه شود.

## نسخه فعلی — GitHub / Arabic / Admin

- نسخه عربی مستقل در `ar/` با `lang="ar"` و `dir="rtl"` و متادیتای عربی جداگانه است.
- پرچم زبان عربی از فایل محلی `assets/flag-saudi.svg` استفاده می‌کند؛ پرچم فارسی از `assets/flag-iran.svg` استفاده می‌کند.
- متن‌های عربی صفحه مستقل هستند و نوشته‌های فارسی داخل تصویر به عنوان ترجمه نمایش داده نمی‌شوند.
- تصاویر روی کاشی‌های محصولات حذف شده‌اند؛ کلیک روی کاشی و پنجره اطلاعات محصول دست‌نخورده باقی مانده است.
- پنل مدیریت شامل محصولات، موجودی، آپلود WebP، بنرها، تخفیف‌ها، دسته‌بندی‌ها، محتوای صفحه، سفارش‌ها، عودت، کیف پول و جستجوی پروفایل با کد مشتری است.
- برای تغییرات واقعی بین همه کاربران، `localStorage` کافی نیست و باید پنل به بک‌اند/دیتابیس متصل شود.
- محدودیت تک-IP پنل فقط در سمت سرور قابل اجرای مطمئن است؛ middleware نمونه در `server/admin-ip-lock.mjs` قرار دارد. GitHub Pages به تنهایی نمی‌تواند این قفل را اجرا کند.

- لوگوی جدید در `assets/ahura-logo.webp` جایگزین لوگوی قبلی شد.
- هدر فارسی و عربی با متن HTML واقعی بازطراحی شد تا لوگو، حساب کاربری، ورود/ثبت‌نام، جستجو و سبد خرید قابل استفاده باشند.
- منوی بالای «تماس با ما»، «پرفروش‌ها» و «تخفیف‌ها» حذف شد.
- انتخاب زبان با پرچم ایران/عربستان و منوی بازشونده به سمت پایین فعال است.
- شمارنده سبد خرید پس از افزودن کالا به‌صورت خودکار تغییر می‌کند و تعداد هر محصول در صفحه حساب کاربری با دکمه‌های کم/زیاد قابل ویرایش است.
- نسخه عربی نیز با همان قالب و قابلیت‌ها به‌روزرسانی شد.


## وبلاگ و شبکه‌های اجتماعی

صفحهٔ عمومی وبلاگ در `blog.html` و نسخهٔ عربی در `ar/blog.html` اضافه شده است. مقاله‌ها بر اساس تاریخ آخرین به‌روزرسانی از جدید به قدیم نمایش داده می‌شوند و بازدیدکننده می‌تواند با دسته‌بندی‌ها فیلتر کند و مقاله را در پنجرهٔ مطالعه باز کند. در پنل مدیریت، بخش «مدیریت وبلاگ» برای ایجاد، ویرایش، انتشار/پیش‌نویس، حذف، دسته‌بندی و تصویر شاخص مقاله قرار گرفته است.

در بخش «شبکه‌های اجتماعی» پنل مدیریت می‌توان نشانی اینستاگرام، تلگرام، روبیکا و سروش را ثبت یا پاک کرد. فقط شبکه‌هایی که نشانی دارند در فوتر فروشگاه و وبلاگ نمایش داده می‌شوند. اطلاعات این نسخه مانند سایر بخش‌های استاتیک در `localStorage` همان مرورگر ذخیره می‌شود.


## انتشار مستقیم روی GitHub Pages

این پروژه به‌صورت **Static Site** آماده شده و برای اجرا به Node.js، PHP، دیتابیس یا build command نیاز ندارد. فایل `.nojekyll` و گردش‌کار `.github/workflows/pages.yml` اضافه شده‌اند؛ بنابراین بعد از push شدن پروژه روی شاخهٔ `main` یا `master`، GitHub Actions فایل‌های همین پوشه را به‌عنوان سایت منتشر می‌کند.

برای انتشار، یک Repository جدید در GitHub بسازید، محتوای داخل این پوشه را در ریشهٔ Repository قرار دهید، سپس commit و push کنید. در GitHub از مسیر `Settings → Pages`، گزینهٔ `Source` را روی `GitHub Actions` بگذارید. بعد از پایان اجرای workflow، نشانی سایت معمولاً به شکل `https://USERNAME.github.io/REPOSITORY/` خواهد بود. صفحهٔ فروشگاه در مسیر اصلی و وبلاگ در مسیر `blog.html` قرار دارد.

اگر نخواهید از Actions استفاده کنید، می‌توانید در `Settings → Pages` گزینهٔ `Deploy from a branch`، شاخهٔ `main` و پوشهٔ `/ (root)` را انتخاب کنید؛ این پروژه بدون build هم اجرا می‌شود. چون مسیرهای فایل‌ها نسبی هستند، در Repositoryهای معمولی نیز از داخل پوشهٔ پروژه درست بارگذاری می‌شوند.

توجه: پنل مدیریت و سبد خرید در GitHub Pages فقط داده‌های همان مرورگر را با `localStorage` نگه می‌دارند و برای چند کاربر یا ذخیره‌سازی واقعی به بک‌اند نیاز دارند.
